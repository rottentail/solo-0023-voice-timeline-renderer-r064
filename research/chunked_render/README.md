# 驻留混音 → 分块处理：可行性研究与否证实验（本轮不改生产实现）

本目录是**离线研究台**，不被任何生产代码引用。`internal/` 与 `cmd/` 在本轮保持
零改动（可用 `git diff --stat -- internal/ cmd/ go.mod` 验证为空）。研究台以只读
方式导入生产包 `internal/audiocodec` 作为参照实现，所有"正确/错误分块方案"都在
`main.go` 内独立实现并与旧管线逐字节对比。

复现：

```bash
go run ./research/chunked_render            # 报告写入 results/experiment_report.json 并打印摘要
```

实验信号全部由确定性正弦 WAV 与固定种子随机数生成，无外部素材。

---

## 1. 旧管线的事实清单（哪些输出必须保持一致）

对照 `internal/render/render.go` 的阶段顺序，一次渲染对外可观测的契约是：

1. **PCM 字节**：`EncodePCM16` 输出的 44 字节头 + 量化后的 int16 载荷，最终由
   `sha256` 摘要固定进回执与 `OutputAsset`。
2. **源选区**：每个 span 的 `source_start_frame/source_end_frame`、输出位置
   `output_start/output_end`、增益、交叉淡化帧数、声道动作（`ReceiptSpan`）。
3. **回执测量事实**：归一化前峰值 `BeforePeakDBFS`、应用增益 `AppliedGainDB`、
   对**最终编码字节重新解码后**测得的 `OutputPeakDBFS / OutputRMSDBFS`、总帧数、
   输出摘要、警告列表。
4. **作业生命周期事实**：`queued→rendering→finalizing→completed`，失败时终态
   `failed` 且不暴露任何已发布半成品。

分块改造的验收标准因此不是"总帧数对"或"峰值差不多"，而是：同一输入下
**输出 WAV 逐字节相同、回执各字段逐值相同（浮点按位相同）、状态机语义相同**。

## 2. 各阶段能否单遍流式化

| 阶段 | 单遍流式？ | 依据 / 必须保存的额外事实 |
|---|---|---|
| WAV 解析与源解码 (`DecodeWAV`) | 可以，但本研究不要求 | 源是不可变资产且已落盘；渲染只需按选区随机读取。真正流式化需要一个**分帧读取器**而非整段 `[]byte`，属于独立改造面。 |
| 选区切片 (`SliceFrames`) | 可以 | 半开区间 + 帧对齐，只需起始/结束帧两个标量；无跨帧状态。 |
| 线性重采样 (`Resample`) | 可以 | 线性插值每个输出帧最多读两个相邻源帧，只需保留**至多 1 个源帧的回看**。输出帧数公式 (`ScaledFrames`) 可在不看信号的情况下先行算出。 |
| 声道映射 (`MapChannels`) | 可以 | 逐帧独立（mono↔stereo 只看当前帧），无跨帧状态。 |
| 增益 | 可以 | 逐样本常数乘法。 |
| 等功率交叉淡化与混音 (`mixPrepared`) | **有条件可以** | 权重只依赖 span 内**绝对帧号** `frame`（`mixer.go:32-37`），与块边界无关；但一个输出帧可能同时被最多 N 个 span 写入（本实验构造了三 span 交叠）。要求：(a) 按 span 顺序重放"先对旧值乘 outgoing、再加 incoming"的运算次序；(b) 用**绝对输出帧号**定位，淡化进度绝不允许从块头重新计数；(c) 块内只保留当前块缓冲，但准备阶段的 span 元数据（输出区间、淡化帧数、增益、各 span 已映射片段）必须全程驻留。 |
| 峰值归一化 (`normalizePeak`) | **不能在发射同一遍内完成** | 增益 `target / 全局峰值` 需要完整信号的 `max|x|`。单遍发射时该事实尚不存在。这是结构性依赖，不是实现技巧问题。 |
| int16 量化与 WAV 编码 (`EncodePCM16`) | 可以 | 量化逐样本独立；44 字节头中的长度字段在准备阶段（纯元数据）已确定，可先写头再增量追加 PCM。研究台 `wavStreamer/buildWAV` 已验证增量编码与整段编码逐字节相同。 |
| 回执测量 (`Measure` over 重新解码的字节) | 可以，但要复刻数值语义 | 峰值是与顺序无关的 max，可流式；RMS 是平方和，可流式但**求和树形状会改变 float64 结果**（见第 5 节）。 |

### 结论：两遍是保持字节一致的最小结构

- **第 A 遍（事实遍）**：分块混音，只产出标量事实——全局归一化前峰值
  `prePeak`（float64）、样本计数；不保存任何整段信号。
- **第 B 遍（发射遍）**：用 A 遍得到的全局增益，重新分块混音、增益、削峰、
  量化、增量写 PCM，同时流式累计后置 peak/RMS。两遍可以使用**不同块大小**
  （实验中 B = A/2+1），证明块边界不携带任何状态，状态只在标量事实里。

任何声称"单遍"却先把全部样本写盘再分块读回的方案，都只是把整段驻留从内存
搬到磁盘，本研究明确不承认其为单遍流式。

## 3. 实验设计与否证的两个错误方案

### 3.1 主信号：严格三片段交叠，且淡化窗跨多种边界

三个源（48 kHz 立体声、24 kHz 单声道、48 kHz 立体声），三个 span，输出 38 帧、
立体声：

- span A：输出 `[0,16)`，无淡化；
- span B：24 kHz 源重采样到 48 kHz，输出 `[2,26)`，淡化窗 `[2,16)`，14 帧；
- span C：输出 `[14,38)`，淡化窗 `[14,26)`，12 帧。

两个淡化窗相交于 `[14,16)`：**第 14、15 帧同时收到 A、B、C 三个 span 的加权
贡献**，且其中一个淡化边界（16）与另一淡化窗内部（26）都会被实验块尺寸
`1,2,3,4,5,6,8,11,16,23,32,37` 中的多个切开。所有块尺寸都严格小于总帧数 38。

### 3.2 正确方案（two-pass）

A 遍分块混音累计 `prePeak`；B 遍用不同块大小重混、套用同一个全局增益、逐样本
量化并流式拼 WAV。后置测量严格复刻生产语义（见第 5 节）。

**结果：12/12 种块边界下，输出与旧管线逐字节相同（SHA-256 相同），回执事实
全部按位匹配。**

### 3.3 错误方案 W1：单遍 + 块内局部峰值归一化（否证"峰值可局部化"）

发射某块时全局峰值尚不存在，于是每块用自己的局部峰值算增益。

**结果：12/12 边界全部产生不同 PCM（2–73 个样本不同），但总帧数 12/12 正确。**
这直接否证"帧数对声音就对"：局部化增益破坏了跨块的统一电平，而帧计数根本不
检测它。

### 3.4 错误方案 W2：块隔离混音，淡化帧号从块头重新计数（否证"块可独立混音"）

每个块从零开始计算淡化进度，而不是用 span 内绝对帧号。

**结果：12/12 边界全部产生不同 PCM（44–48 个样本不同），差异帧区集中在被边界
切开的淡化窗内；总帧数仍然 12/12 正确。** 对照实验：无交叉淡化的单 span 信号
下，W2 在块尺寸 1/3/7 时**逐字节相同**——证明 W2 的危害精确地来自跨边界淡化，
而非分块本身。

### 3.5 固定种子 fuzz

4 个固定种子（11/29/47/83）的随机几何，经独立诊断确认分别含 10/5/7/2 个真实
三 span 交叠帧；每个种子再用 6 种块尺寸（1,2,3,5,7,13）测试：正确方案全部
字节+事实匹配，W1/W2 全部被否证。结论不依赖手工信号。

## 4. 资源上界（N = 输出总帧数，C = 声道数，B = 块帧数，S = span 数）

| 资源 | 旧整段驻留 | 正确两遍分块 |
|---|---|---|
| 混音浮点驻留峰值 | `O(N·C)` 个 float32，一次性 | `O(B·C)` 个 float32，单块；实验中 B 最小为 1（立体声仅 2 个样本） |
| 归一化需要的整段信号 | 必需 | **0**：只保留 `prePeak`、计数等标量 |
| 输出缓冲 | 完整 WAV `O(N·C·2 + 44)` 字节 | `O(B·C·2)` 的 PCM 追加缓冲 + 44 字节头（可直接写文件/`io.Writer`） |
| 跨块必须保留的事实 | — | 每 span 元数据 `O(S)`（区间、淡化帧数、增益、选区）；全局标量 `prePeak`、`postPeak`、`sumSquares`、样本计数 |
| 已映射源片段 | 整段 clip 驻留 | 本研究台仍保留已映射 clip（`O(S·span长度)`）；生产化时这是下一个可独立优化的驻留项，可改为按需重解码，**不影响**本研究的混音/归一化结论 |
| CPU 时间 | 一遍混音 + 一遍归一化 | 两遍混音（约 2 倍混音工作量），编码仍一遍；用额外一遍换取有界内存 |
| 磁盘 | 仅最终发布 | 取消时仅 `tmp/` 内临时文件，发布前不产生可见文件 |

关键上界：**内存不再随 N 增长，只随 B 与 S 增长**；代价是混音计算量约翻倍，
以及必须接受两遍结构（全局峰值无法绕过）。

## 5. 必须保存/复刻的额外事实（含两个容易踩的数值坑）

研究过程中两个坑都实际导致了"字节相同但回执对不上"，因此写成硬约束：

1. **全局归一化前峰值**：一个 float64 标量，A 遍逐块取 max。峰值与遍历顺序
   无关，分块不改变其值。没有它就只能退回 W1 的错误局部归一化。
2. **int16 解码的非对称除数与 float32 中间舍入**：`DecodeWAV` 对负码用
   `/32768.0`、非负码用 `/32767.0`，结果存为 **float32**。后置测量必须先做这一
   精确还原；在 float64 里直接除法会得到不同的 peak/RMS，即使 PCM 字节完全
   相同（研究台 `decodedFloat16` 复刻此行为）。
3. **平方精度**：生产 `Measure` 的循环变量是 float64 副本，`value*value` 是
   **float64 平方**再累加进 float64 和。研究台一度误用 float32 平方，导致 RMS
   系统性偏差（约 2e-8 dB）；探针实验确认 float64 平方才与 `Measure` 按位相等。
4. **RMS 求和顺序（独立压力实验，`stress.go`）**：用序列 `1.0` 后接 4096 个
   `2^-53`（1.0 的半个 ulp）重复两组：
   - 旧管线式**单标量顺序累加**（块只是工作单元，不产生块内部分和）在 8 种
     块尺寸下与旧结果**全部按位相同**；
   - "每块先求部分和、结束后再合并"的自然分块写法在 8 种块尺寸中的 4 种
     得到不同总和（最大 RMS 偏差约 2.6e-12 dBFS）。
   约定：流式 RMS 只允许维护**一个按帧序更新的全局标量累加器**，不得保留
   每块部分和再合并；若未来要并行合并部分和，必须同时在回执契约中声明该
   数值变化，不能默默改数。
5. **量化器分支**：`sample <= -1 → -32768`、`>= 1 → 32767`、负值乘 32768、
   非负乘 32767 并 `Round`（`quantizeInt16` 逐分支复刻），否则字节不会相同。
6. **span 放置与淡化用绝对帧号**：`OutputStartFrame` 等在纯元数据准备阶段即可
   全部算出，是跨块事实；淡化进度 `(frame+0.5)/xf` 中的 `frame` 是 span 内
   绝对序号，W2 证明了重编号的后果。

## 6. 取消后的事实（`demonstrateCancellation`，实验已实测）

在第 3 块（块大小 3，处理完输出帧 0–8 共 9 帧、写出 36 字节 PCM 到 `tmp/` 内
临时文件）后取消 context：

- 作业停在活动态可转 `failed`；已写出的内容只存在于**私有 staging 临时文件**，
  实验确认其在清理前存在（36 字节）、清理后不存在，`renders/` 发布树无任何
  半成品，回执不写入、输出摘要不产生。
- 取消时标量事实（部分峰值/部分和）是不完整的，**不得**被发布或用于恢复；
  恢复约定为**从头重跑**：实验中以新的块尺寸（A=5、B=7）重跑后与参考输出
  SHA-256 相同，证明不依赖任何取消前残留。
- 检查点若要落盘，只能落在 `tmp/` 且发布前整体删除；本轮不实现检查点恢复。

## 7. 旧工程复现的可落地约定

1. **确定性输入**：源 WAV 字节、timeline JSON、`target_peak_dbfs`、输出声道/
   采样率完全相同即定义同一渲染；实验所有信号程序化生成、可重复。
2. **冻结的数值契约**（写进未来实现的注释与测试）：非对称 int16 除数、
   float32 解码中间值、float64 平方与单标量顺序累加、量化分支、淡化绝对帧号、
   削峰先于量化。
3. **金标准对拍**：以当前整段驻留实现的输出 WAV（SHA-256）与回执为 golden，
   分块实现的验收是**逐字节 + 回执逐值**，在块尺寸集合
   `{1,2,3,4,5,6,8,11,16,23,32,37}`（含 1 帧极端块与接近 N 的块）以及固定种子
   fuzz 上全部相等；帧计数相等仅作为必要不充分条件。
4. **状态机与发布纪律不变**：沿用 `tmp/` 暂存 + 目录 rename 原子发布
   （`storage.CommitRenderArtifacts`），失败清理临时目录，回执仍只在输出字节
   原子提交后写入。
5. **两遍之间不发布任何东西**：A 遍结束只在内存持有标量事实；B 遍结束才进入
   `finalizing`。若未来允许 A 遍事实落盘，文件必须位于 `tmp/` 且随作业终结
   清理，不进入数据模型。
6. **块大小是内部调参，不进回执**：实验证明同一块大小集合内输出与边界无关，
   因此回执 schema（`schema_version: 1`）无需变化；任何改变求和树/量化路径的
   "优化"都必须先升 schema 版本并给出迁移对拍。

## 8. 实验结论一览（与 `results/experiment_report.json` 对应）

- 正确两遍方案：12/12 边界字节相同、摘要相同、回执事实按位相同；4/4 fuzz
  种子 × 6 块尺寸同样成立。
- W1（局部峰值单遍）：12/12 字节不同，帧数全对 → 否证"单遍局部归一化"。
- W2（块内淡化重编号）：12/12 字节不同，帧数全对，差异落在跨边界淡化帧；
  无淡化对照组完全相同 → 否证"块可独立混音"，并定位根因。
- RMS：单标量顺序累加 8/8 与旧值按位相同；块部分和合并 4/8 漂移。
- 取消：staging 临时文件可观测、清理后零发布物、从头重跑摘要一致。
